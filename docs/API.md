# API

Full interactive documentation (auto-generated by FastAPI from the Pydantic
schemas) is served at `/docs` (Swagger UI) and `/redoc` when the backend is
running. This file is a map, not a duplicate of that reference.

Base path: `/api/v1`. Authenticated endpoints expect
`Authorization: Bearer <access_token>`.

## Error shape

Every error response (raised via `app.core.exceptions.AppError` subclasses)
has the same shape:

```json
{ "error": { "code": "not_found", "message": "Competency not found" } }
```

Unhandled exceptions return `500` with `{ "error": { "code": "internal_error", "message": "Internal server error" } }`; the stack trace is only logged server-side. `GET /health/ready` returns `503` with `{ "status": "unavailable" }` when the database is unreachable.

## Pagination

Lists that grow per user are paginated with `limit`/`offset` query params
(helper: `app/api/pagination.py`). The response body is still a plain JSON
array; the total number of matching rows is in the `X-Total-Count` response
header (exposed via CORS).

| Param | Default | Constraints |
|---|---|---|
| `limit` | `50` | `1..200`; outside that range returns `422` |
| `offset` | `0` | `>= 0`; negative returns `422` |

Paginated: `GET /study-sessions` (newest first), `GET /goals` (newest first),
`GET /reviews/due` (oldest due first). Ordering is deterministic (ties broken
by `id`). Small catalogs (subjects, competencies, achievements, learning
paths, quests, challenges, resources) are not paginated. There are currently
no list endpoints for XP awards or challenge submissions; add the same
dependency when they are introduced.

## Endpoints

| Method & Path | Auth | Purpose |
|---|---|---|
| `GET /auth/registration-info` | — | `{enabled, invite_required}` signup policy |
| `POST /auth/register` | — | Create account, returns tokens. Optional `invite_code`; 403 if closed or bad code; 429 when rate limited |
| `POST /auth/login` | — | Returns tokens |
| `POST /auth/refresh` | — | Rotate: exchange a refresh token for a new access+refresh pair; the presented token is invalidated. Reusing it returns 401 and revokes all the user's sessions |
| `POST /auth/logout` | Bearer | Body `{refresh_token?}`. Revokes the current access token and the given refresh token. 204 |
| `GET /auth/me` | ✓ | Current user |
| `GET /subjects` | ✓ | List subjects with competency count + average mastery |
| `GET /subjects/{id}` | ✓ | Subject detail: competencies with computed skill-tree state |
| `GET /learning-paths` | optional | List learning paths with their competency sequence. With a valid bearer token each path has `progress` (`total_steps`, `mastered_steps`, `average_mastery` 0-100) and each item `mastery_score` + `state` (`locked`/`available`/`learning`/`mastered`); all `null` when anonymous. An invalid token returns 401 |
| `GET /learning-paths/{slug}` | optional | Learning path detail, with the same per-step and aggregate progress fields as the list |
| `POST /study-sessions` | ✓ | Log a study session (awards XP, recomputes mastery, schedules review) |
| `GET /study-sessions` | ✓ | Recent study sessions |
| `POST /goals` | ✓ | Create a learning goal |
| `GET /goals` | ✓ | List the current user's goals |
| `PATCH /goals/{id}/status` | ✓ | Update goal status (active/achieved/archived) |
| `GET /competencies/{id}/challenges` | ✓ | Challenges for a competency |
| `POST /challenges/{id}/submissions` | ✓ | Submit a self-assessed pass/fail (awards XP once, on first pass) |
| `GET /reviews/due` | ✓ | Spaced-repetition reviews currently due. Each item also carries `competency_name`, `subject_id` and `subject_name` (single joined query) |
| `POST /reviews/{competency_id}/recall` | ✓ | Submit a recall quality (0-5), advances the SM-2 schedule |
| `GET /gamification/profile` | ✓ | XP, level, streaks |
| `GET /gamification/achievements` | ✓ | All achievements with earned/unearned status |
| `GET /gamification/quests` | ✓ | Active quests with live progress (auto-completes on target) |
| `GET /dashboard` | ✓ | Aggregate: level/XP/streak + active goals + due reviews + weakest competencies + recent sessions |
| `GET /health` | — | Liveness probe |
| `GET /health/ready` | — | Readiness probe (checks DB connectivity) |
